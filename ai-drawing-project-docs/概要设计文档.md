# **“幻境画廊” AI绘画平台 \- 概要设计文档 V1.1**

## **1\. 系统架构 (System Architecture)**

本系统采用业界成熟的**前后端分离**架构，并结合**消息队列**与**内存缓存**实现核心任务的异步处理与性能优化，确保了系统的响应性、鲁棒性和可扩展性。

### **1.2. 核心流程描述**

1. **任务提交 (REST API)**: 用户在前端配置好参数后，点击“生成”按钮。前端通过HTTPS协议，向Spring Boot后端发起一个RESTful API请求（例如 POST /api/v1/ai-drawing/generate）。在提交前，后端可通过Redis进行API速率限制，防止恶意请求。  
2. **实时通知 (WebSocket)**: 前端在加载时，会与Spring Boot后端建立一个持久化的WebSocket连接，用于接收任务完成的实时通知。  
3. **任务入队 (AMQP \- Produce)**: Spring Boot后端接收到API请求后，进行参数校验，然后将包含所有生成参数的任务消息发送到RabbitMQ的消息队列中，并立即向前端返回“任务已入队”的响应。  
4. **任务出队 (AMQP \- Consume)**: 后端的某个消费者服务 (DrawingTaskConsumer) 持续监听该队列。一旦有新任务入队，它会立即获取并开始处理。  
5. **AI生成 (WebSocket)**: 消费者服务与ComfyUI引擎建立WebSocket连接，发送格式化的生成指令。ComfyUI执行耗时的AI计算，完成后将图片信息返回给消费者。  
6. **数据持久化 (JDBC & Cache Update)**: 消费者服务在从ComfyUI获取图片后，将其保存到本地文件系统，并将作品元数据写入MySQL数据库。如果该作品被分享到画廊，后端会主动清除(evict)画廊的Redis缓存，以确保下次请求能获取到最新的数据。  
7. **结果通知 (WebSocket)**: 数据持久化完成后，后端通过一个特定的事件通知机制，触发一个通知服务，向特定的前端用户推送“任务完成”的消息。  
8. **数据查询与缓存 (Cache-Aside Pattern)**: 当用户请求公共画廊等热点数据时，后端会首先查询Redis缓存。  
   * **缓存命中 (Hit)**: 如果在Redis中找到数据，则直接将数据返回给前端，极大提升响应速度。  
   * **缓存未命中 (Miss)**: 如果Redis中没有数据，后端会再去查询MySQL数据库，然后将查询结果存入Redis缓存（设置合理的过期时间），最后再将数据返回给前端。

## **3\. 部署架构 (Deployment Architecture)**

在初始阶段，所有服务（Spring Boot, RabbitMQ, MySQL, Redis, ComfyUI）可以通过docker-compose在单一服务器上进行容器化部署，简化管理和运维。

随着业务量的增长，未来可以演进为分布式的微服务架构：

* **数据库**：迁移到云厂商提供的RDS服务（如AWS RDS for MySQL），实现高可用和自动备份。  
* **缓存**：使用云厂商提供的托管Redis服务（如AWS ElastiCache），实现高可用和弹性伸缩。  
* **文件存储**：从本地存储迁移到云对象存储（如AWS S3, 阿里云OSS），实现无限扩展和CDN加速。  
* **后端服务**：将Spring Boot应用部署到Kubernetes(K8s)集群，实现服务的弹性伸缩和故障自愈。  
* **AI引擎**：可以部署专门的GPU服务器集群来运行ComfyUI，并通过负载均衡进行调度。
