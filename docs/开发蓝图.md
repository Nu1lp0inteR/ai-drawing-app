## **Phase 1: 性能优化与体验完善 (已完成)**  

* **目标**: 引入Redis提升核心性能，并补全核心的用户体验闭环，让平台从"可用"变为"好用且快"。  
* **已交付成果** (2026-05-28):  
  1. **【高优】画廊缓存与分页**: Redis `@Cacheable` 启用，画廊 API 迁移到 `/api/v1/gallery`，支持分页（`page`/`size`）。`@CacheEvict(allEntries=true)` 在分享/取消分享时清除全部页缓存。  
  2. **【高优】画廊作品详情**: `GET /api/v1/ai-drawing/{drawingId}` 已实现（带 `@Cacheable` 1h）。`ArtworkDetailModal.vue` 展示完整参数（prompt / negative_prompt / steps / cfg / sampler_name / seed），含下载原图 + 复制提示词按钮。  
  3. **【中优】个人作品历史**: `GET /api/v1/ai-drawing/my-history`（分页）已实现。新建 `History.vue`（路由 `/history`），双源合并（IndexedDB 本地作品 + 服务端已分享作品），支持删除、分享、加载更多。  
  4. **【低优】"一键复用"功能**: 画廊详情模态框和 History.vue 均支持"复用参数"，通过 `sessionStorage` → `pushState` → `Studio.vue` `onMounted`/`onActivated` 读取并预填表单。  
  5. **【新增】画廊 UI 惊艳功能**: CSS 渐显动画 + 悬停特效、IntersectionObserver 无限滚动、空状态引导页（"去创作" CTA）、生成进度阶段提示。  
  6. **【新增】基础设施加固**: `@ControllerAdvice` 全局异常处理、`DrawingRequest` 添加 `@Valid` 校验、`api/index.js` axios 实例 + 拦截器、JWT 提取统一到 `JwtService.getCurrentUserId()`、SecurityConfig 路径修复、死代码清理。

## **Phase 1.5: 数据库持久化重构 (建议周期: 1-2天)**  

* **背景**: Phase 1 的"双源合并"（IndexedDB + 服务端 API）是为了快速交付的临时方案。当前 `DrawingTaskConsumer` 仅在用户分享时写入 `drawings` 表，未分享的作品仅存于浏览器 IndexedDB（最大 50 条，换浏览器丢失）。这导致 Phase 2 的点赞、排行榜等功能缺少服务端 `drawing_id`。  

* **目标**: 消除 IndexedDB 与服务端的双源复杂度，让绘图在生成时即入库。Phase 2 的社区功能（点赞、排行、评论）需要每条 drawing 有稳定的服务端主键。  

* **与评审结果的一致性**:  
  - CEO 评审中"保持双源"是为了快速交付 Phase 1 —— 已兑现  
  - Phase 1.5 不推翻任何已接受的评审决策，是自然的技术债务偿还  
  - History.vue 和 IndexedDB 代码保留不动，数据源从"合并两个"变为"服务端为主 + IndexedDB 降级为缓存"  

* **关键任务**:  
  1. **【高优】生成即入库**:  
     * **后端**: `DrawingTaskConsumer.receiveDrawingTask()` 中 ComfyUI 返回图片后，立即创建 Drawing 记录（`shared_to_gallery=false`）。图片仍通过 WebSocket 推送 base64 到前端，不改变现有通知机制。  
  2. **【高优】统计修正**:  
     * **后端**: `ProfileService.getUserStats()` 原来只统计 `drawings` 表中已存在的记录。入库后统计自动准确，无需额外改动。  
  3. **【中优】History.vue 简化**:  
     * **前端**: 移除 IndexedDB 与服务端的合并逻辑，改为纯服务端分页查询（`GET /my-history`）。IndexedDB 保留但降级为"近期作品快速展示缓存"（不做合并，仅做首屏加速）。  
  4. **【低优】前端适配**:  
     * `Profile.vue` 和 `Studio.vue` 中的 IndexedDB 读写保持不动（向下兼容）。新增数据以服务端记录为准。  
     * 分享后 IndexedDB 删除逻辑已有（Phase 1 已加固），无需额外改动。  

* **不与 Phase 1 冲突的点**:  
  - `GET /my-history` 端点已存在（返回分页的 drawing 列表），只需确认 IndexedDB 合并逻辑移除后不破坏现有体验  
  - `POST /api/v1/ai-drawing/share` 流程不变（multipart → 存文件 → 标记 `shared_to_gallery=true`）  
  - 画廊分页、详情模态框、参数回填等 Phase 1 功能完全不受影响  

* **对 Phase 2 的解锁**:  
  - 点赞需要稳定的 `drawing_id` → 入库后每条作品都有  
  - 排行榜需要统计维度 → 入库后可查询所有作品的点赞/浏览量  
  - 模型选择需要关联 drawing 记录 → 入库后参数完整可追溯

## **Phase 2: 社区化与服务治理 (预计周期: 3-4周)**

* **目标**: 引入社区互动元素，并基于Redis实现初步的服务治理，提升用户粘性和系统稳定性。  
* **关键任务**:  
  1. **【高优】API速率限制**:  
     * **后端**: 利用Redis和AOP（切面编程）实现一个注解@RateLimit，并应用到generate等关键API上。  
  2. **【中优】点赞与热门排行**:  
     * **后端**: 扩展数据库。设计点赞API。使用Redis的Sorted Set实时更新热门作品排行榜。  
     * **前端**: 在画廊和作品详情中添点赞按钮，并开发新的“排行榜”页面。  
  3. **【中优】模型选择**:  
     * **后端**: 设计API以获取ComfyUI中可用的模型列表（可缓存）。修改任务提交逻辑以支持模型参数。  
     * **前端**: 在 Studio.vue 中添加模型选择的下拉框。  
  4. **【低优】作品评论**:  
     * **后端**: 设计 comments 表和相关API。  
     * **前端**: 在作品详情页添加评论区功能。

## **Phase 3: 长期演进与商业化探索**

* **目标**: 扩展平台能力，探索可持续的运营模式。  
* **关键任务**:  
  1. **高级绘图功能**:  
     * 逐步支持“图生图”、“ControlNet”、“局部重绘”等更复杂的AI绘画工作流。  
  2. **分布式会话管理**:  
     * 将用户会话（JWT黑名单等）从内存管理迁移到Redis，为后端服务的水平扩展做准备。  
  3. **商业化探索**:  
     * 为重度用户提供基于订阅的Pro账户，提供更快的生成队列、独占的GPU资源或更多的存储空间。  
     * 引入积分系统，用户可以通过每日签到等方式获取积分，用于图片生成。  
  4. **多平台支持**:  
     * 开发移动端应用或响应式布局，优化移动端体验。
